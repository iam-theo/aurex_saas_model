# aurex/

Aurex is an AI agent execution platform: isolated Docker workspaces where an
AI agent (opencode) performs real work, streamed live to the user.

## Layout

- `apps/api` — Express REST + SSE, port 4010, `npm run dev:api` (from repo root)
- `apps/worker` — BullMQ worker for Docker lifecycle + agent runs, `npm run dev:worker`
- `apps/web` — React/Vite portal, port 5173, `npm run dev:web`
- `packages/db` — Prisma schema (`prisma/schema.prisma`), client generated by `db:push`/`db:generate`
- `packages/docker` — dockerode helpers for workspace containers
- `packages/shared` — shared types/constants
- `docker/workspace` — workspace image; rebuild with `npm run workspace:build`
  (build is slow: apt + global `opencode-ai@1.18.15`)

## Environment & services

- Root `.env` is loaded via `--env-file=../../.env` in the api/worker start
  scripts (tsx does NOT auto-load `.env`).
- Postgres is a docker container on **5435** (`aurex`/`aurex`, db `aurex`).
- Redis is the **host redis on 6379** (no container; BullMQ warns about
  redis 6.0 < 6.2 but works). Do not set REDIS_URL to 6380.
- Docker Hub pulls are flaky on this host — reuse cached images where
  possible (`postgres:16-alpine` is cached locally).

## Commands

```bash
npm install
docker compose up -d postgres
npx prisma db push --schema packages/db/prisma/schema.prisma
npm run db:seed --workspace @aurex/db
docker build -t aurex-workspace:latest docker/workspace   # or: npm run workspace:build
npm run dev:api  # + dev:worker + dev:web
```

Typecheck: `npx tsc --noEmit -p apps/<app>/tsconfig.json` per package.

## Gotchas

- The workspace container image has `tail -f /dev/null` as entrypoint; agent
  runs are `docker exec`'d in via `packages/docker` (`aurex-agent` script).
- `opencode run --format json --auto` must be used so the agent is autonomous
  and emits structured events; the worker stores them as `AgentEvent` rows and
  relays them over Redis pub/sub to the API's SSE endpoint.
- When killing processes, `pkill -f tsx` also matches the worker/api under
  `npm run` — use explicit pids or `pkill -9 -f "apps/<app>/src/index.ts"`.

## Deploying changes (AUTO via aurex-deploy)

The production site `https://<your-domain>/` (e.g. `https://aurex.example.com`) serves a **static Vite build**
at `/var/www/html/aurex/` (nginx), with `/api` proxied to localhost:4010. The
PM2 `aurex-web` process is only the dev server — restarting it does NOT update
the site. Set `AUREX_PUBLIC_BASE_URL` and `AUREX_PUBLISH_DOMAIN` via the installer.

Deploys are **automatic**: the PM2 app `aurex-deploy`
(`scripts/deploy-watch.mjs`) watches `apps/{api,worker,web}/src`,
`packages/{shared,docker}/src` and `packages/db/prisma`, then on every change:

```bash
npm run build --workspace @aurex/web
rm -f /var/www/html/aurex/assets/* && cp apps/web/dist/index.html /var/www/html/aurex/ \
  && cp -r apps/web/dist/assets /var/www/html/aurex/
pm2 restart aurex-api aurex-worker --update-env
```

It debounces 800ms and runs under PM2 (survives restarts). Changes in the
watched dirs are deployed automatically — no manual step needed.

For manual deploys (or if `aurex-deploy` is down), run the three commands above
and verify: `pm2 ls | grep aurex` (all online),
`curl -s -o /dev/null -w "%{http_code}" http://localhost:4010/api/projects` (200),
and `curl -s https://<your-domain>/api/projects` (200).

Prisma schema changes are watched but NOT auto-applied — run
`npm run db:push` manually and restart `aurex-api`/`aurex-worker`.
